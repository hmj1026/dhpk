# Next.js 15.5

Version-specific guidance for the 15.5 line. 15.6 never shipped stable (canary-only) before the jump to 16.0, so there is **no `nextjs-15.6` module**. That is the feature-lane boundary. It is not a claim that 15.5 patch releases stopped at v15.5.19.

Checked on 2026-10-21:

- <https://github.com/vercel/next.js/releases/tag/v15.5.20> is a stable
  release (`prerelease=false`, 2026-07-01).
- <https://github.com/vercel/next.js/releases/tag/v15.5.21> is a stable
  release (`prerelease=false`, 2026-07-21) whose notes list security fixes.
- The same feed's newest stable 15.5 tag that day was v15.5.28
  (2026-10-14). That tag is an observation, not a final 15.x patch.
- <https://nextjs.org/support-policy> listed 15.x as Maintenance LTS
  (release date on that page: Oct. 21, 2024) and said each major remains
  in Maintenance LTS for two years following the initial release.
  Re-check the page before treating that status as current.

These patch tags are historical examples. They are not a minimum patched version.

## Signature features

### `next typegen`

Introduced in 15.5.0. Generates TypeScript definitions for routes and
route params, writing to `<distDir>/types`, without running a full
`next build`:

```bash
next typegen
```

### Stable typed routes

`typedRoutes` is promoted out of `experimental` — it is now a
top-level `next.config` key (requires TypeScript in the project):

```js
/** @type {import('next').NextConfig} */
const nextConfig = { typedRoutes: true }
module.exports = nextConfig
```

### Beta Turbopack production builds

```bash
next build --turbopack
```

Turbopack production-build support was experimental in 15.3.0 and
became **beta** in 15.5.0. Turbopack for `next dev` has been
**stable since 15.0.0**. In 15.5, Turbopack is **not yet the
default** for builds — you opt in with the flag; its absence still
means webpack.

### AMP support deprecated

AMP support is deprecated in the 15.x line.

## Migration traps

### `next lint` deprecated

`next lint` is deprecated in 15.5 (scheduled for removal in 16 —
cross-reference `the selected Next.js 16 guidance`). Migration path off it is the
ESLint CLI directly; a codemod automates the swap:

```bash
npx @next/codemod@canary next-lint-to-eslint-cli .
```

Note: projects already using a non-ESLint linter see no build-time
lint step run automatically once `next lint` is dropped.

### 15.5 patches are not a 15.6 feature lane

15.6 never went stable (canary only before the jump to 16.0). Do not expect a `nextjs-15.6` module; a major upgrade from this guidance goes to 16. Patch maintenance on 15.5 is a different fact: v15.5.19 is not the last 15.x patch. Use the dated release feed and support policy in the introduction. Do not promote one later patch number into a new terminal version, and do not read the examples as a minimum upgrade.

## What's missing compared to 16

- **Turbopack is not yet the default** — still opt-in via
  `--turbopack` for `next build` (stable default arrives in 16)
- **`next lint` still exists** — deprecated but present; removed in
  16
- **Synchronous access to Request APIs** (`params`, `searchParams`,
  `cookies`, `headers`) still has a compatibility shim in 15.5 — 16
  removes it (async-only)
