# Flow Drive standalone portability

Use this contract when installing or moving Flow Drive independently, or when
an available helper supplies reusable task evidence. Copy the complete Skill
directory, preserving its relative resource paths and file modes. A partial
copy with a missing required module remains blocked at that local resource.

The public entry is `scripts/run.js`, exporting
`runFlowDrive(argv, { host, workdir, authorizationEvidence, recovery })`.
It resolves dispatch and policy contracts from its own
`references/execution-bundle/` and CLI-role resources from
`references/cli-dispatch/`. The invocation parser and other runner helpers live
in `scripts/`. Consumers do not reconstruct missing resources from parent
directories, another checkout, sibling skills, or root environment variables.
The canonical authoring workflow synchronizes bundled resources before
distribution; consumers receive physical copies.

The Host supplies task interpretation, current capability evidence,
coordination, execution, and acceptance verification through the documented
runner hooks. Workspace writers additionally require scope inspection. Supply
an actual task-input file with bound prompt identity, assigned write scope, and
the existing Provider consent contract. Current evidence can correct a stale
catalog only when bound to this Host session, executor binding, target, role,
and authority. Moving the Skill preserves those checks and does not grant a
Provider, model, or tool.

The portable runner supports the same native solo task, dependency-ordered
coordination, and explicitly granted external target selections as its source
contract. It starts with external probing disabled. An answered Provider scope
or trusted authorization evidence permits only the selected target's scoped
capability refresh. Unselected external Providers remain unprobed even when the
answer includes them.

Peer skills, optional capability descriptions, and helper tools can contribute
evidence through the same task and result contracts. Their absence does not
block a task the injected Host can execute and verify with its available tools.
A prior diagnosis may be reused when prompt, task, baseline, and current Host
verification remain valid. A missing necessary reasoner conclusion or observed
reviewer independence produces its concrete dispatch or acceptance blocker;
an unavailable helper name does not substitute for that evidence. Fresh
prerequisite results invalidate dependent reuse as described in
[recovery](recovery.md).

The environment must provide a Node runtime satisfying the selected release's
declared version, the injected Host hooks, and access to the task workspace.
A selected external CLI route additionally depends on that CLI, usable
authentication, available model/quota, and Host access/capability evidence.
Native execution uses the current Host's available runtime. The copied Skill
does not carry accounts, credentials, every Provider CLI, or every Host tool.

The relocation probe copies only Flow Drive into a blank consumer, removes
module search fallback, and uses trusted module and filesystem guards to deny
canonical checkout and sibling visibility. It imports the copied public runner,
injects fake Host hooks and plain fixture data, and verifies actual assigned
effects, terminal reports, receipts, scoped refreshes, reused diagnosis, and
missing reviewer independence. The guards are fixture controls, not an OS
sandbox. These results are relocation/stub `PASS`; real Host/Provider runtime
remains `NOT_RUN` and formal Supported combinations do not expand from them.

Formal distribution artifacts are generated by their canonical owners from a
clean committed source, then checked as separate consumer/package evidence.
Pending source edits, generated package validation, publication, and live
runtime each retain their own completion state. Generated outputs are refreshed
through the distribution workflow rather than edited inside a consumer copy.
